How it works

1. Run it on the Mac

Install Ollama, pull a model (ollama pull llama3.2), then run npx github:VedSoni-dev/berth serve in Terminal. It prints a QR code.

2. Scan it with your phone

Same Wi-Fi, the camera app. The chat opens with the pairing code in its address; add it to your Home Screen.

3. Ask from your phone

The Mac runs the model and streams the answer back, with tokens per second and "running on" your Mac above it.

What works

The phone app

Served by the Mac. Streaming answers, a model picker with the Mac's Ollama models, Stop, light and dark, one-handed at 390 px, installable to the Home Screen.

A pairing code

In the QR code, checked on every request; nothing answers without it. --new-token unpairs every phone.

No dependencies

One small Node server, a QR encoder and a static app. Nothing goes through a server of ours.

The dashboard

Shows the command and whether a phone is paired. Also runs a small model in a tab on WebGPU, or connects Ollama for a local OpenAI-compatible endpoint.

Any OpenAI-compatible server

Ollama by default; --ollama <url> points it at LM Studio or llama.cpp instead.

Away from home

Put the Mac and the phone on Tailscale and open the Mac's Tailscale address. berth has no relay of its own.

Not yet

  • No memory pooling: one model can't be split across several Macs; each runs whole models.
  • No menu-bar app yet: it's a Terminal command. No relay besides Tailscale.
  • Many Android phones can't open .local names: run berth serve --ip.

Run it from a clone

git clone https://github.com/VedSoni-dev/berth
cd berth && npm run serve      # the Mac server and phone app
npm install && npm run dev     # the site and dashboard
